## 1. 좌표 구조
- `Q4 = ZMod 4 × ZMod 4` (16) — 터미널 A2 fiber (`TerminalQ 4`).
- `Y = ZMod 4`, `Z = ZMod 4`.
- **RootState (K₅(4)) = Q4 × Y × Z**, 크기 16·4·4 = 256 = 4⁴. ✓
- 터미널 carrier `F_i := terminalSymbolStep 4 TerminalSymbol.Fi` (i=0,1,2), 각 16-cycle.
- 리셋 워드 `W = F1∘F2∘F0` (16-cycle, `terminalResetTrace4`, decide✅).

## 2. 5색 return (R̂₀..R̂₄ on Q4×Y×Z)
1차 lift (Q4×Y, 64-cycle):
```
T_i(q,y) = (F_i q, y + 1_{q=p_i})      i=0,1,2   p0=(0,0),p1=(1,0),p2=(2,2)
P0(q,y)  = (F0^{1_{y=0}} q, y+1)
P1(q,y)  = (F1^{1_{y=3}} F2^{1_{y=2}} F0^{1_{y=1}} q, y+1)   # 1 circuit = W
```
2차 lift (Z, 256-cycle):  `R̂_i(x,z) = (R_i x, z + 1_{x=a_i})`
```
a0=((0,0),0) a1=((0,0),1) a2=((0,0),2) a3=((0,0),3) a4=((0,1),0)
(R0..R4) = (T0,T1,T2,P0,P1)
```

## 3. 단일순환 경로 (Bundle B, 기존 자산)
| 색 | 1차 lift 단일순환 | 2차 lift |
|---|---|---|
| 0,1,2 (T_i) | `pointCarrySingleCycle`: base=F_i(16-cycle), crossing=p_i, a=1 → carry 합=1(unit) | `pointCarrySingleCycle`: base=R_i(64-cycle), crossing=a_i, a=1 |
| 3 (P0) | word-skew: base Y(4-cycle, y+1), fiber Q4, monodromy F0(16-cycle) → 64-cycle | `pointCarrySingleCycle` Z-lift |
| 4 (P1) | word-skew: monodromy W(16-cycle, decide✅) → 64-cycle | `pointCarrySingleCycle` Z-lift |

선결: 개별 `F_i`(F0/F1/F2)의 16-cycle을 decide로 확보(현재는 word `terminalTrace4`/
`terminalResetTrace4`만 증명됨 — 개별 F_i, F0 단독, W는 추가 decide 필요할 수 있음).

## 4. schedule 실현 (paper "realize by layer rows")
- 터미널 A2 layer word + Y-row + Z-row(neutral) 곱 + 5개 local substitution
  (Table D54-reset-ports). 각 치환 = Latin row 안 2-entry 교환 → rowLatin·layerBijective
  보존(P2 `partialExchange*`). support 분리 → `switching-ribbons`로 정확히 위 return 실현.
- m=4 layer. Y가 height 역할(매 return마다 y+1, 4회에 1 circuit).

## 8. 구조적 pivot — `EvenV11/LowD5M4Structural.lean` (2026-06-04, sorry/native_decide 無)

사용자 결정에 따라 native_decide blob에서 **논문 구조적 경로**로 전환. 이 파일은
엔진-적용 reduction 정리 하나를 제공한다 (typecheck ✅, sorry·native_decide 없음):

```lean
theorem finalLowD5M4RootFlatCertificateFamily_of_returnRealization
    (dir : ZMod 4 → RootState → TorusColor 5 → TorusDirection 5)   -- RootState = Fin 4 → ZMod 4
    (e   : Seed ≃ RootState)                                       -- Seed = (Q4 × Y) × Z
    (hRow   : (LowD5M4Schedule.schedule dir).rowLatin)
    (hLayer : (LowD5M4Schedule.schedule dir).layerBijective)
    (hReal  : ∀ c x, e.symm ((LowD5M4Schedule.schedule dir).returnMap c (e x))
                       = LowD5M4.fullReturn c x) :
    FinalLowD5M4RootFlatCertificateFamily
```

**이 정리가 (제가) 닫은 것 (엔진 적용):**
- **RF3 `returnsSingleCycle`**: `hReal` + 이미 구조적으로 증명된
  `LowD5M4Seed.fullReturn_singleCycle`(unit-carry 256-cycle)을
  `single_cycle_of_equiv_conj e`로 운반. → 256-cycle을 native_decide로 열거하지
  않고 구조적으로 확보.
- **stepConjugacy**: `LowD5M4Schedule.stepConjugacy_of_dir dir` (dir 무관, 무료).
- **family 승격**: `finalRootFlatTorusCertificate_of_fields` →
  `finalLowD5M4RootFlatCertificateFamily_of_certificate`.

**사용자가 채울 것 (handoff):** 위 5개 가설.
- `dir` — 터미널 A2 layer word × Y-row × neutral Z-row + Table D54-reset-ports의
  5개 2-entry 치환(folded+reset 색칠). m=4라 좌표 명시적.
- `e` — 추상 skew tower 좌표 `(Q4×Y)×Z` ↔ 표준 root-flat section `Fin 4 → ZMod 4`
  의 동치. (256↔256; `dir`/realization과 함께 co-design.)
- `hRow`/`hLayer` — RF1/RF2. **유한**(t∈ZMod 4, c∈Fin 5, w 256개)이라 `dir`이
  concrete해지면 plain `decide` 후보 (native 불필요). 커널 `decide`가 느리면
  P2 `partialExchange`(2-entry 교환이 Latin 보존)로 구조적 증명.
- **`hReal` — 진짜 hard math (the genuine handoff).** `returnMap c`는
  `step = rootStep`(실제 generator move e_δ−e_0)의 4-layer 합성이고,
  `fullReturn c`는 터미널 carrier `F_i = terminalSymbolStep`(generator move 아님)
  기반. 둘이 켤레임은 논문 §11 마지막 문단 "realize these return maps by layer
